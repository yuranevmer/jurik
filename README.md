# jurik

Инструменты, которые собирают git-репозиторий `build/laws/` с Конституцией и кодексами
Украины и полной историей их изменений:

- рабочая копия `main` = действующий официальный текст, один markdown-файл на статью;
- история `main` = история законов: каждый закон, менявший кодекс, это ветка
  `bill/<созыв>/<номер законопроекта>` с коммитом правок и merge в `main`, датированным днём
  принятия; автор ветки = первый инициатор, автор merge = Верховна Рада України;
- законопроекты, не ставшие законом (отклонены, отозваны, сняты, на рассмотрении), это ветки
  `bill/*` без merge с текстом законопроекта в `bills/<созыв>/<номер>.md`.

Цели: чтение человеком, `git log` / `git blame` по статье, датасет для LLM на любую дату.
Реестр кодексов (25 записей, 26 документов zakon) лежит в `codes.yaml`.

## Источники и обязательное указание источника

- **zakon.rada.gov.ua** («Законодавство України»): тексты всех редакций кодексов. Берутся
  через открытый API `https://data.rada.gov.ua/laws/card/<nreg>.json` (список редакций и
  підстав) и `https://data.rada.gov.ua/laws/show/<nreg>/ed<YYYYMMDD>` (HTML редакции),
  `User-Agent: OpenData`.
- **data.rada.gov.ua** (открытые данные Верховной Рады, созывы III–IX): законопроекты, связь
  законопроект ↔ закон, инициаторы, этапы, голосования «в цілому», тексты законопроектов.

Подробности форматов: `docs/spike-sources.md`.

Данные © Верховна Рада України. Условия использования zakon.rada.gov.ua и data.rada.gov.ua
требуют указывать источник: при публикации `build/laws`, экспорта или производных данных
ссылайтесь на zakon.rada.gov.ua и data.rada.gov.ua. Сгенерированный `build/laws/README.md`
и `manifest.json` экспорта (`sources`) содержат эту ссылку. Собранный репозиторий не является
официальной публикацией.

## Установка и проверки

```
uv sync
uv run jurik --help
uv run pytest          # сетевые тесты (@pytest.mark.network) выключены; -m network включает
uv run ruff check
```

Нужны `uv`, Python ≥ 3.12 и `git` в `PATH`.

## Команды CLI

```
jurik fetch   [--code SLUG] [--refetch]
jurik rada    [--convocation N] [--refetch]
jurik parse   [--code SLUG] [--edition YYYYMMDD] [--all]
jurik build   [--code SLUG ...] [--linear] [--bills-limit N] [--out build/laws]
jurik report  [--code SLUG ...] [--repo build/laws]
jurik export  [--at YYYY-MM-DD] [--with-bills] [--repo build/laws] --out DIR
```

| Команда | Что делает |
|---|---|
| `fetch` | Карточки и все действующие редакции кодексов в `cache/zakon/` (gzip). Rate limit, повторы; кеш никогда не чистится, `--refetch` перекачивает. Все 25 кодексов: ≈ 2,5 ч, 2847 редакций, 520 МБ. |
| `rada` | Открытые данные Рады (все созывы или `--convocation`) в `cache/rada/`, строит индекс законов и печатает покрытие. |
| `parse` | Парсит редакции из кеша и проверяет полноту текста (мультимножество слов print-версии = слова отрендеренных файлов). По умолчанию последняя редакция каждого документа, `--all` = все. Сбои → `report/parse-failures.md`. |
| `build` | Пересоздаёт `--out` с нуля через `git fast-import` и проверяет инварианты (`check_repo`). Требует в кеше все действующие редакции выбранных кодексов. `--linear` = история без веток. `--bills-limit N` ограничивает число веток не принятых законопроектов (самые ранние по регистрации); без опции строятся все. Тексты законопроектов докачиваются в `cache/rada/bills/`. |
| `report` | `report/coverage.md` (покрытие по кодексам, коммиты/ветки из `--repo`) и `report/parse-failures.md`; парсит все кешированные редакции (≈ 7 мин). |
| `export` | Состояние `main` на дату `--at` (по трейлеру `In-force:`, без даты = сегодня) в папку markdown + `manifest.json`. `--with-bills` добавляет `bills/**/*.md` не принятых законопроектов, зарегистрированных до `--at`, с пометкой «Не є чинним законом». |

Типичный полный прогон: `jurik rada`, `jurik fetch` (для каждого кодекса или всех сразу),
`jurik parse --all`, `jurik build`, `jurik report --repo build/laws`.

Каталоги `cache/`, `build/`, `report/` в git не коммитятся.

## Как читать `build/laws`

`build/laws` — самостоятельный git-репозиторий (его можно опубликовать отдельно и
клонировать как обычный: `git clone <url> laws`). Внутри есть `README.md` на украинском,
его генерирует `jurik build` (см. ниже).

```
cd build/laws
git log --first-parent main                       # законы в порядке вступления в силу
git log --first-parent --format='%h %(trailers:key=In-force,valueonly) %s' main
git log --follow -- codes/tax/01-zahalni-polozhennia/art-0014.md   # история статьи
git blame -- codes/constitution/01-zahalni-zasady/art-0005.md
git show <merge>                                  # правки одного закона
git diff bill/9/6173^ bill/9/6173                 # то же из ветки законопроекта
git branch --no-merged main --list 'bill/*'       # законопроекты, не ставшие законом
```

### Две оси времени

- **Порядок `main` = порядок вступления редакций в силу.** Каждый коммит `main` несёт
  трейлер `In-force: YYYY-MM-DD`; «состояние на дату» = последний коммит `--first-parent
  main` с `In-force:` ≤ дате. Так работают `jurik export --at`, инварианты и приёмка.
- **Committer/author date merge-коммита = дата принятия закона.** Поэтому даты коммитов
  вдоль `main` могут идти не по возрастанию (закон, принятый раньше, может вступить в силу
  позже), и `git log --before/--since` не даёт состояние на дату. Коммит ветки датирован
  днём регистрации законопроекта. Время всех коммитов = 12:00 по Europe/Kyiv.

### Раскладка

```
README.md                         генерируется builder'ом, лежит в первом коммите main
codes/<slug>/
  _meta.yaml                      title, zakon_id, adopted, source_url, status, edition_date
  preamble.md                     текст до первого структурного уровня
  closing.md                      подпись, место и дата принятия («Президент України …»)
  NN-<translit>/                  уровень: книга, частина, розділ, підрозділ, глава, §
    provisions.md                 заголовок уровня (# Розділ I. …) + текст уровня вне статей
    art-NNNN.md                   статья
bills/<созыв>/<номер>.md          только в ветках bill/* не принятых законопроектов
```

- Номер папки выводится из номера в источнике (римские → арабские), индекс сохраняется:
  `Глава 1-1` → `01-1-…`, буквенный суффикс главы КЗпП `Глава III-А` → `03-a-…`. Транслит
  КМУ-2010, не длиннее 40 символов.
- Статья `art-0014.md`, с индексом `art-0039-1.md`, двухуровневый индекс КК
  `art-0096-10-1.md`. Два подряд идущих одинаковых номера статьи в источнике (КАС
  2016–2017, «Стаття 183-7» дважды) → второй файл `art-0183-7_2.md`, заголовок сохраняет
  номер источника.
- `provisions.md` есть у каждого уровня и начинается с его заголовка, даже если уровень
  содержит только статьи; неструктурированные перехідні/прикінцеві положення лежат в нём как
  есть.
- Особые виды уровней: `final` — ненумерованные «ПРИКІНЦЕВІ ТА ПЕРЕХІДНІ ПОЛОЖЕННЯ» ЦК (папка
  без номера `prykintsevi-ta-perekhidni-polozhennia/`); `group` — ненумерованные подзаголовки
  внутри § ЦК (`# 2. Повне товариство`); «I. ЗАГАЛЬНА ЧАСТИНА» / «II. ОСОБЛИВА ЧАСТИНА»
  КУпАП — уровень ранга підрозділ (`02-osoblyva-chastyna/`, заголовок
  `# II. ОСОБЛИВА ЧАСТИНА`).
- Исключённая статья остаётся файлом-заглушкой `# Стаття N. Виключена`. Редакторские
  примечания `{…}` в текст не входят.
- КУпАП (два документа zakon 80731-10 и 80732-10) собран в одну папку `admin-offences`.
- Утративший силу кодекс удаляется из `main` коммитом `Reason: repealed`: Господарський
  кодекс 2025-08-28 (закон 4196-IX); `export --at` более ранней даты его содержит.
  Житловий оставлен действующим (утратил силу «крім окремих положень», редакции утраты нет).
- Путь в репозитории только ASCII; имена веток проходят `ref_safe` (`1234-д` →
  `bill/4/1234-d`, `/` → `_`).

### Модель веток

| Случай | В репозитории |
|---|---|
| Первая доступная редакция кодекса | коммит в `main`, `Reason: initial` |
| Закон-підстава | ветка `bill/<созыв>/<номер>` от `main`, действовавшего на дату регистрации законопроекта; коммит с change set; merge в `main` |
| Тот же закон, следующий этап вступления в силу | ещё один коммит той же ветки (`Stage: 2`) и повторный merge |
| Несколько підстав в одной редакции | один коммит с несколькими `Law:`, `Reason: multiple`; ветка названа по первому закону |
| Закон без законопроекта в open data (в основном до 1998 г.) | ветка `bill/law/<nreg>`, `Bill: unknown` |
| Решение КСУ / редакция без підстави / прочая підстава | линейный коммит `main`, `Reason: court` / `unknown` / `other` |
| Утрата силы кодекса | коммит `main`, удаляет папку, `Reason: repealed` |
| Законопроект к кодексу, не ставший законом | ветка `bill/<созыв>/<номер>` с одним коммитом `bills/<созыв>/<номер>.md`, без merge |

Коммит ветки содержит только правки этого закона (`git diff bill^ bill`), merge = `main` +
те же правки = новый официальный текст.

### Трейлеры сообщений

| Трейлер | Где | Значение |
|---|---|---|
| `Law:` | main, ветки | номер закона (`2856-VI`) |
| `Bill:` | main, ветки | `<созыв>/<номер>` или `unknown` |
| `Adopted:` | main | дата принятия и голоса «в цілому» (`за 268 / проти 2 / утрималися 1`) |
| `Signed:` | main | дата подписания |
| `In-force:` | main (обязателен) | дата вступления редакции в силу |
| `Stage:` | main, ветки | этап вступления в силу одного закона |
| `Reason:` | main | `initial`, `law`, `multiple`, `court`, `unknown`, `other`, `repealed` |
| `Basis:` | main | підстава, не являющаяся законом (решение КСУ и т.п.) |
| `Edition:` | main | редакция zakon `<zakon_id>/edYYYYMMDD` |
| `Source:` | main, ветки | ссылка на закон на zakon или на карточку законопроекта |
| `Registered:` | ветки | дата регистрации законопроекта |
| `Status:` / `Status-date:` | ветки без merge | `rejected` / `withdrawn` / `removed` / `pending` и дата текущей фазы |
| `Co-authored-by:` | ветки | остальные инициаторы |

### Инварианты (`check_repo`, при каждом `build`)

(a) каждая редакция ровно в одном коммите `main` с её `In-force:`; (b) `In-force:` вдоль
`--first-parent main` не убывает; (c) текст `main` каждого действующего кодекса по словам
совпадает с print-версией последней редакции; (d) каждая ветка закона влита в `main` ровно
один раз своим концом.

## Текущая сборка (2026-10-26)

`jurik build --bills-limit 500`: 1312 с, `.git` 78 МБ, 4083 коммита (1808 в `--first-parent
main`), 2047 веток `bill/*` (1547 влитых + 500 без merge), 0 нарушений. Подробно:
`docs/pilot-build.md`, приёмка там же; пилот парсера: `docs/pilot-parse.md`.

## Известные ограничения

- **Ветки не принятых законопроектов ограничены 500** (`--bills-limit 500`: самые ранние,
  созывы III–IV) из 7362. Полный прогон: `uv run jurik build` без `--bills-limit`
  (≈ 2–3 ч загрузки текстов, загрузки кешируются, повторный запуск продолжает).
  `--bills-limit 0` строит только историю `main` (≈ 5 мин).
- **Тексты законопроектов в Word 97 `.doc` не конвертируются** (77 из 500): ветка содержит
  заглушку «Текст недоступний» со ссылкой на карточку. Также 3 документа IX созыва, на
  которые API itd.rada.gov.ua отвечал HTTP 500. Конвертируются rtf, html, docx, pdf.
- **Законы без собственной редакции на zakon**: 11 событий истории карточек без редакции
  несут 12 законов (КУпАП 3+3 события, КпН, КТМ, ГПК, ВК, ЛК); их правки попадают в diff
  следующей редакции, а коммит называет только её підставу (пример: `Закон № 2350-III`
  в КУпАП несёт ещё 2342-III, 2359-III, 2360-III, 2362-III, 2372-III).
- **Первая редакция старых кодексов не исходный текст**: zakon не хранит текст при
  принятии (КЗпП 1971 → первая доступная редакция 1996, Житловий 1983 → 1984, КУпАП и др.),
  поэтому коммит `initial` = самая ранняя доступная редакция.
- **Multi-basis редакции не разделяются** по законам (227 коммитов `Reason: multiple`).
- **Omnibus-законопроекты** «до деяких законодавчих актів», не называющие кодекс, не
  сопоставляются с кодексами (поиск по названию; 96% таких не найдено), поэтому их
  отклонённые варианты не попадают в ветки.
- 1% законов-підстав (30, в основном до 1998 г.) отсутствует в открытых данных (ветки
  `bill/law/*`, без инициаторов и голосов); у 8% редакций нет голосования «в цілому».
- Редакционная правка самого zakon (вставленные ссылки «( 1103-2011-п )», исправление
  опечаток) попадает в diff ближайшего закона.
- Кодекс про надра: заголовок документа остаётся в `preamble.md` (косметика).
- Сборка всегда с нуля, инкрементального режима нет; будущие (ещё не действующие) и
  условные редакции не берутся.
