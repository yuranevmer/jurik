## TL;DR

- Связь «законопроект ↔ закон» есть в открытых данных и покрывает практически всё:
  `bills_acts-skl<N>.csv` (III–IX) и поле `actNumber` в `billinfo-skl9.json` (IX). Для каждого
  законопроекта со статусом «Закон підписано» в III–IX есть строка акта (777/778 в III, 100% в IV–IX).
  Підстави редакций 7 кодексов находятся в этих таблицах на 99–100%; не находятся только законы
  II скликання (1994–1998, `/96-вр`, `/97-вр`) и закон с буквенным суффиксом `2147а-19`.
- Обратная связь тоже есть: JSON-карточка закона `https://data.rada.gov.ua/laws/card/<nreg>.json`
  содержит `projs` (номер законопроекта, созыв, ссылка на карточку).
- У data.rada.gov.ua есть официальный API к «Законодавству України» (User-Agent `OpenData`):
  JSON-карточка со списком всех редакций и підстав в виде nreg и HTML текста любой редакции.
  Это надёжнее, чем разбирать HTML карточки zakon (см. ⚠️ в Task 3–5 плана).
- Голосования «в цілому» есть для III–IX в `/ogd/zal/ppz/skl<N>/plenary_*`; связываются с
  законопроектом по номеру в повестке/названии события (IX: 1735 из 1811 законов, 96%).
- Тексты законопроектов: ссылки есть в открытых данных, но форматы разные: III–VIII отдают
  html/rtf/doc через `webproc34`, IX отдаёт pdf/docx через chunked API itd.rada.gov.ua.
- Блокеров нет. Модель веток сужать не нужно.

## data.rada.gov.ua: как найти файлы

- Каталог: `https://data.rada.gov.ua/ogd/list.json`, `https://data.rada.gov.ua/ogd/<group>/list.json`.
- **Манифест набора**: `https://data.rada.gov.ua/ogd/<path>/meta.json` (например
  `/ogd/zpr/skl9/meta.json`). Поле `item[]`: `id`, `name`, `format` (`csv` или
  `csv:<size>,json:<size>,...`), `size`, `path`, `pubDate`, `archived`.
  `list.json` внутри набора даёт 404, страница `/open/data/<id>` грузит список динамически.
- **URL файла** = `https://data.rada.gov.ua` + `path` + `name` + `.<format>`. Если `name` уже с
  расширением (`doc.txt`), то `path + name`. Одноформатные наборы также лежат как
  `<name>.zip` (в 6–20 раз меньше); у многоформатных (`bills_main`, `plenary_agenda`) zip нет (404).
- Кодировка: данные и большинство каталогов UTF-8; каталоги `/ogd/zal/` и `/ogd/zak/` и
  страницы ошибок отдаются в windows-1251. 404 приходит как HTML-страница в cp1251.
- `billinfo-skl9.json` содержит управляющие символы в строках: `json.loads(..., strict=False)`.

### Номер закона: нормализация

- `act_number` в CSV в отображаемом виде: `229-IX`, но 1/3 номеров IX набраны кириллицей
  (`229-ІХ`, `IХ`). Нормализовать `І→I`, `Х→X`.
- Отображаемый суффикс неоднозначен: `322-VIII` это 1971 год (nreg `322-08`), а `1-VIII` это 2014
  (nreg `1-19`); законы III созыва бывают и `650-XIV`, и `2947-III` (оба nreg `-14`).
  **Ключ закона = nreg (zakon id)**: `<номер>-<NN>`, где III→14 (и XIV→14), IV→15, V→16, VI→17,
  VII→18, VIII→19, IX→20; II созыв `<номер>/<YY>-вр`; XII (I созыв) `-12`.
  На zakon nreg видно в `href` підстави (`/laws/show/4834-17`), отображаемый текст `4834-VI`.
- Буквенный суффикс: `2147<sup>а</sup>-VIII`, nreg `2147а-19`; в `bills_acts` не нашёлся
  (единичный случай, допустимо `bill/law/…`).
- В `bills_acts` есть и постанови (номер того же вида), поэтому строк актов больше, чем законов.

### Голосования (`/ogd/zal/ppz/skl<N>/`, есть для III–IX)

- `plenary_agenda-skl<N>.csv`: `date_agenda, id_question, number_question (номер законопроекта), init_question, name_question`.
- `plenary_event_question-skl<N>.csv`: `date_agenda, id_question, date_question, type_event, date_event, name_event, id_event`; голосования = строки с `id_event`, `name_event` вида «Поіменне голосування про проект Закону … (№15532) - в цілому».
- `plenary_result_event-skl<N>.csv`: `id_event, for, against, abstain, not_voting, total, presence, absent, voting_result` (1 = принято).
- `plenary_vote_results` (TSV, 73 МБ IX) и `plenary_result_by_name` (336 МБ IX): поимённо, для плана не нужны.
- Стыковка: событие с «в цілому» (без «скасування рішення»), номер законопроекта из
  `plenary_agenda.number_question` по `id_question` или из `№NNNN` в `name_event`; дата
  события = `actDate`. IX: 1735 из 1811 подписанных законов найдены, 1731 в тот же день.
- Размеры для IX: event_question 15 МБ, result_event 1.2 МБ, agenda 5.1 МБ; III: 6.5 / 0.45 / 1.5 МБ.

### Тексты законопроектов

- III–VIII: `bills_documents.document_type`, текст законопроекта помечен **«Проект Закону»**
  (и «Проект Закону (на заміну)», «Проект Кодексу»); остальное: «Пояснювальна записка»,
  «Порівняльна таблиця», «Подання», «Висновок …», «Текст, підписаний Головою Верховної Ради України».
  `document_url` = `http://w1.c1.rada.gov.ua/pls/zweb2/webproc34?id=&pf3511=<bill>&pf35401=<doc>`,
  ответ `application/octet-stream` с `Content-Disposition: filename="doc_<id>.<ext>"`. Форматы
  по выборке: III html (cp1251), V rtf, IX(CSV) doc (Word 97). Не только docx/pdf.
- IX (`billinfo`): `documents.source[kind="Проєкт Закону"].docFiles[type="Проєкт Закону"]`
  (рядом `Пояснювальна записка`, `Порівняльна таблиця`, `Подання`, `Проєкт Постанови до Закону`);
  форматы текста законопроекта: pdf 8361, docx 1560. Финальный текст: `workflow[kind="Текст,
  підписаний Головою Верховної Ради України"]`.
  `docFiles.url` (`/billInfo/Bills/pubFile/<id>`) отдаёт HTML-страницу с JS. Сам файл:
  `GET https://itd.rada.gov.ua/billinfo/api/file/download/` с заголовками `X-File-Id: <id>`,
  `X-Current-Chunk: 0..`; ответ содержит заголовки `Size`, `ChunkSize`, `Type` (MIME). Файл
  328 КБ пришёл одним чанком.

## zakon.rada.gov.ua и OpenData API «Законодавство України»

`https://data.rada.gov.ua/ogd/zak/laws/readme.txt`: API требует `User-Agent: OpenData` (без него 302).

- `https://data.rada.gov.ua/laws/card/<nreg>.json`: JSON-карточка. `eds[]{datred (YYYYMMDD),
  pidstava ("2853-15,2901-15", nreg через запятую), podid, size, comment}`, `history`
  (`"20020110:4:|20030101:0:407-15|20090203:25:v003p710-09|..."` = дата:тип события:підстави),
  `nazva`, `orgnum` (`2947-III`), `orgdat`, `status`, `projs[]` (законопроект этого акта:
  `proj_num`, `proj_dat`, `proj_nam`, `url` с `skl=<созыв+1>`). Слэш в nreg не кодировать
  (`/laws/card/213/95-вр.json`; `%2F` даёт 404).
  Для самого кодекса `projs` часто указывает на «Пропозиції Президента», а не на исходный проект.
- `https://data.rada.gov.ua/laws/show/<nreg>/ed<YYYYMMDD>`: HTML редакции, абзацы `<p><a name="nNNN"></a>…</p>`
  без классов `rvps`; индекс статьи как `Стаття 39 - 1 .` (с пробелами). Без `/ed…` текущая
  редакция (Податковий 7.9 МБ).
- `.../ed<YYYYMMDD>.txt` есть, но **теряет индексы**: `Стаття 39-1` превращается в `Стаття 391`
  (Податковий: дубли 191, 192, …). Для парсинга не годится.
- Массовые наборы: `/ogd/zak/laws/data/csv/doc-update.txt` (редакции всех документов, 17.7 МБ,
  zip 2.6 МБ), `ist.txt` (история и підстави, 32 МБ), `doc.txt` (карточки, 52 МБ); схемы
  `/ogd/zak/stru/doc-stru.csv`, `ist-stru.csv`.

### Карточки zakon (HTML) и самые ранние редакции

Блок `<section id="History">`, строки `<tr>`: дата `<span class="dat1">`, текст события
(«Прийняття», «Редакція, підстава - <a href=…/laws/show/<nreg>>…</a>», «Визнання
неконституційними окремих положень», «Тлумачення», «Втрата чинності»), третья колонка со
ссылкой `/laws/show/<id>/ed<YYYYMMDD>` и меткой «перша / попередня / поточна / наступна /
остання редакція». Текущая редакция ссылки на `ed…` не имеет (метка «відкрито зараз»).

| Кодекс | первая событие | самая ранняя редакция с текстом | что это |
|---|---|---|---|
| КЗпП 322-08 | 10.12.1971 «Прийняття», **текст відсутній** | ed19960723, підстава 256/96-ВР | сводный текст 1996 года, не исходный 1971 |
| Житловий 5464-10 | 30.06.1983 «Прийняття», текст відсутній | ed19840101 «Введення в дію», підстава 5465-X | текст на вступление в силу; дальше ed19930101 «Редакція» **без підстави** |
| Водний 213/95-ВР | 06.06.1995 «Прийняття» | ed19950606 | исходный текст |
| Конституція | 28.06.1996 | ed19960628 | исходный текст, 10 редакций |
| Сімейний | 10.01.2002 | ed20020110 | исходный текст, 63 редакции (62 датированных + 1 условная) |
| Податковий | 02.12.2010 | ed20101202 | исходный текст, 242 редакции |
| Цивільний | 16.01.2003 | ed20030116 | исходный текст, 184 редакции |

Значит для старых кодексов «перша редакція» в карточке это **не** текст при принятии: коммит
`initial` должен датироваться датой первой доступной редакции и нести её підставу, а не датой
принятия кодекса.

### Особенности данных карточек

- **Несколько підстав в одной редакции**: Податковий 43 редакции (ed20120101: 7 законов),
  Сімейний 3, КЗпП 8, Цивільний 19.
- **Один закон в нескольких редакциях**: Податковий 18 законов (`4834-VI` в ed20120701,
  ed20120721, ed20121216 и ещё в multi-basis ed20130101), Цивільний 2, Житловий 1, Водний 1.
- **Підстава-КСУ**: в виде zakon id решения `v020p710-10` (Конституція ed20100930), а не
  `18-рп/2011`. События КСУ без новой редакции («Визнання неконституційними…», «Тлумачення»)
  встречаются во всех карточках и редакцию не дают.
- **Условные редакции без даты**: под заголовком «пізніше», дата текстом («через 6 місяців з дня
  припинення … воєнного стану»), ссылка `ed30000101`, `ed30000102`. В JSON `datred=30000101`
  и `comment`. Это future-редакции.
- **Утрата силы частично**: Житловий 15.02.2026 «Втрата чинності крім окремих положень»
  (підстава 4751-IX) с текстом последней редакции, т.е. папку целиком удалять нельзя.
